# @cratedigger/db

Drizzle ORM schema, the canonical TypeScript types it generates, and the matching `init.sql` for fresh-DB Docker initialization.

## Source of truth

- **Schema:** `src/schema.ts` (Drizzle definitions)
- **Fresh-DB SOT:** `init.sql` (mounted by `docker-compose.yml` on volume init)
- **Migrations (additive):** `migrations/NNN_*.sql`, generated by `drizzle-kit generate`

When `schema.ts` changes:
1. `pnpm db:generate` — emits a numbered migration in `migrations/`
2. Update `init.sql` to match (or run `drizzle-kit introspect` against a fresh DB and copy the result)
3. `pnpm db:push` to apply

## Conventions

Adopted from Sift (see `../../HARVESTED_FROM_SIFT.md`):
- Numbered SQL migration files
- `init.sql` as fresh-DB SOT, migrations are additive-only
- RLS on per-user tables via `current_setting('app.current_user_id', true)`
- Pool `max: 5` (Neon hobby/free cap)

## Local dev

```bash
# From repo root
pnpm db:up                # starts pgvector/pgvector:pg16 on :5432
pnpm db:psql              # opens psql shell
pnpm db:reset             # nukes the volume and reapplies init.sql
```

`init.sql` runs once when the volume is first created. After that, additive
migrations land via `pnpm db:push`.
